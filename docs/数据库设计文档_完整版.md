## 三、建表语句

### 3.1 用户认证模块（5 张表）

#### user — 终端用户表

```sql
CREATE TABLE `user` (
  `user_id`           BIGINT       NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `username`          VARCHAR(50)  DEFAULT NULL            COMMENT '登录账号（手机号/邮箱注册时由服务端生成 user_{user_id} 后回填）',
  `password`          VARCHAR(100) NOT NULL                COMMENT '密码（BCrypt加密）',
  `nickname`          VARCHAR(50)  NOT NULL                COMMENT '昵称',
  `avatar`            VARCHAR(512) DEFAULT NULL            COMMENT '头像URL',
  `phone`             VARCHAR(20)  DEFAULT NULL            COMMENT '手机号',
  `email`             VARCHAR(100) DEFAULT NULL            COMMENT '邮箱',
  `gender`            TINYINT      DEFAULT 0               COMMENT '性别：0未知 1男 2女',
  `bio`               VARCHAR(200) DEFAULT NULL            COMMENT '个人简介',
  `status`            TINYINT      NOT NULL DEFAULT 1      COMMENT '状态：1-正常 0-禁用',
  `continue_sign_day` INT          NOT NULL DEFAULT 0      COMMENT '连续签到天数',
  `last_sign_date`    DATE         DEFAULT NULL            COMMENT '上次签到日期',
  `login_fail_count`  INT          NOT NULL DEFAULT 0      COMMENT '连续登录失败次数',
  `lock_until`        DATETIME     DEFAULT NULL            COMMENT '账号锁定截止时间（NULL为未锁定）',
  `last_login_time`   DATETIME     DEFAULT NULL            COMMENT '最后登录时间',
  `create_time`       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `deleted`           TINYINT      NOT NULL DEFAULT 0      COMMENT '逻辑删除：0-未删除 1-已删除',
  PRIMARY KEY (`user_id`),
  UNIQUE KEY `uk_username` (`username`),
  UNIQUE KEY `uk_phone` (`phone`),
  UNIQUE KEY `uk_email` (`email`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='终端用户表';
```

| 字段 | 类型 | 说明 |
|---|---|---|
| user_id | BIGINT PK | 用户ID |
| username | VARCHAR(50) | 登录账号，唯一。注册时由服务端生成 `user_{user_id}`，用户不可自定义 |
| password | VARCHAR(100) | BCrypt加密密码 |
| nickname | VARCHAR(50) | 昵称 |
| avatar | VARCHAR(512) | 头像URL |
| phone | VARCHAR(20) | 手机号，唯一。邮箱注册时必须写 NULL |
| email | VARCHAR(100) | 邮箱，唯一 |
| gender | TINYINT | 0未知 1男 2女 |
| bio | VARCHAR(200) | 个人简介 |
| status | TINYINT | 1正常 0禁用 |
| continue_sign_day | INT | 连续签到天数，签到成功+1，断签重置为0 |
| last_sign_date | DATE | 上次签到日期，用于判断是否连续 |
| login_fail_count | INT | 连续登录失败次数，成功后清零，达5次触发锁定 |
| lock_until | DATETIME | 账号锁定截止时间，当前时间 < lock_until 时拒绝登录 |
| last_login_time | DATETIME | 最后登录时间 |

> **账号标识落库规则**：`accountType=1`（手机号）写 `phone` 列、`email` 写 `NULL`；`accountType=2`（邮箱）写 `email` 列、`phone` 写 `NULL`。**未使用的一列必须写 `NULL`，不能写空串** —— MySQL 的 UNIQUE 索引允许多个 `NULL`，但只允许一个 `''`。邮箱地址禁止写入 `phone` 列（`VARCHAR(20)` 装不下，会截断或报错）。
>
> **登录查询**：`username` / `phone` / `email` 三选一命中，均需带上 `deleted = 0 AND status = 1`。
>
> **账号锁定机制**：连续5次密码登录失败，设置 lock_until = NOW() + 15分钟，login_fail_count 清零。锁定期间登录返回 1007 账号已锁定。登录成功后 login_fail_count 清零。
> **连续签到**：签到成功时，若 last_sign_date = 昨天，则 continue_sign_day + 1；否则 continue_sign_day = 1。更新 last_sign_date = 今天。

> **第三方登录**：本版不接第三方（微信）登录与账号绑定，`user_third_party` 表已随需求移除；账号体系只走用户名 / 手机号 / 邮箱 + 密码。

#### verification_code — 验证码表

```sql
CREATE TABLE `verification_code` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `target`      VARCHAR(100) NOT NULL                COMMENT '验证码目标（手机号或邮箱）',
  `target_type` TINYINT      NOT NULL DEFAULT 1      COMMENT '目标类型：1-手机号 2-邮箱',
  `code`        VARCHAR(10)  NOT NULL                COMMENT '验证码（6位数字）',

  `expire_time` DATETIME     NOT NULL                COMMENT '过期时间（发送后5分钟）',
  `used`        TINYINT      NOT NULL DEFAULT 0      COMMENT '是否已使用：0-未使用 1-已使用',
  `used_time`   DATETIME     DEFAULT NULL            COMMENT '使用时间',
  `client_ip`   VARCHAR(50)  DEFAULT NULL            COMMENT '请求IP（限流防刷）',
  `send_status` TINYINT      NOT NULL DEFAULT 1      COMMENT '发送状态：1-成功 0-失败',
  `fail_reason` VARCHAR(200) DEFAULT NULL            COMMENT '发送失败原因',
  `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发送时间',
  PRIMARY KEY (`id`),
  KEY `idx_target_scene` (`target`, `scene`),
  KEY `idx_expire_time` (`expire_time`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='验证码表';
```

> **校验逻辑**：查 target + scene 下最新一条未使用且未过期的记录，比对 code；通过后标记 used=1。同一目标同一场景 60 秒内限发一次。
>
> **双通道**：`target_type=1` 走短信网关，`target_type=2` 走邮件服务；发送结果记入 `send_status` / `fail_reason`（如 SMTP 被拒原因）。校验逻辑两条通道一致，无需分表。

| 字段 | 类型 | 说明 |
|---|---|---|

> **双 Token 机制**：
> - 登录成功签发 accessToken（JWT，有效期2小时，不入库）+ refreshToken（随机串，有效期7天，入库）
> - accessToken 过期后，前端用 refreshToken 调用 `/api/v1/auth/refresh` 换取新的 accessToken 和 refreshToken（旧 refreshToken 作废，实现轮转）
> - 登出时将当前 refreshToken 的 status 置 0
> - 定时任务清理过期的 refreshToken 记录

| keyword | VARCHAR(100) | 搜索关键词 |
| user_id | BIGINT | 用户ID，未登录=0 |
| type | TINYINT | 1-文章 2-视频课程 |

> **热词统计机制**：每次搜索写入此表，同时更新 Redis 热词计数（ZINCRBY search:hot:words 1 keyword）。热词Top列表接口直接从 Redis ZREVRANGE 获取，不查库。后台可清空 Redis 热词缓存。定时任务可将 Redis 热词数据归档到数据库做长期分析。

## 五、关键查询与索引对照

### 5.1 内容项列表（分类页 / 搜索页）

`ContentItemDto` 由两张表分别查询后统一拼装，`type` 在服务端写死：

| 排序 | 文章查询 | 课程查询 |
|---|---|---|
| 最新 | `WHERE status=2 AND deleted=0 ORDER BY publish_time DESC` → `idx_status_publish` | `WHERE status=1 AND deleted=0 ORDER BY publish_time DESC` → `idx_status_publish` |
| 最热 | `... ORDER BY view_count DESC` → `idx_status_view` | `... ORDER BY view_count DESC` → `idx_status_view` |

`categoryName` 需 JOIN `content_category`；`authorName` 直接取冗余列（`article.author_name` / `course.instructor_name`），不必 JOIN `user`。

### 5.2 其余高频查询

| 场景 | 查询条件 | 命中索引 |
|---|---|---|
| 我的收藏 | `WHERE user_id=? AND target_type=? AND delete_time=0` | `idx_user_type_time` |
| 我的笔记 | `WHERE user_id=? ORDER BY create_time DESC` | `idx_user_create` |
| 某内容下我的笔记 | `WHERE user_id=? AND source_type=? AND source_id=?` | `idx_user_source` |
| 我的待办 | `WHERE user_id=? AND status=?` | `idx_user_status` |
| 待办提醒扫描 | `WHERE remind_time<=NOW() AND reminded=0 AND status=0` | `idx_remind_time` |
| 顶级评论 | `WHERE target_type=? AND target_id=? AND root_id=0 AND status=1 AND comment_id<?` | `idx_target_root_status` |
| 楼中楼回复 | `WHERE root_id=? AND status=1 AND comment_id<?` | `idx_root_id` |
| 我的课程 | `WHERE user_id=?` | `idx_user_id` |
| 我的下载记录 | `WHERE user_id=? AND resource_type=?` | `idx_user_type_time` |
| 登录 | `WHERE (username=? OR phone=? OR email=?) AND deleted=0` | `uk_username` / `uk_phone` / `uk_email` |
| 文件按 fileId 查 | `WHERE file_id=?` | `uk_file_id` |
| 文件去重 | `WHERE sha256=? AND scene=?` | `idx_sha256_scene` |
