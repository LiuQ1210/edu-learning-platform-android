## 三、关键实现

### 1. 流式问答与回退

`AgentStreamClient` 用 OkHttp WebSocket 连 `ws://<host>/ws/forum?token=<token>`，
连上后先订阅 `user:{userId}`，再 `POST /agent/chat/stream` 拿 `requestId`，
按 `agent.delta` 把增量写进 `AxingUiState.streamingText`，`agent.done` 收尾。

- 只有**连接成功之后**才提交流式请求，避免「用户消息已落库、再回退同步接口」造成重复提问；
- 连接失败（未登录、网关不支持 WS、服务端未开）直接回退同步 `/chat`；
- 中途失败抛错，不做二次提交，避免同一句话落两遍。

**默认关闭流式**：抽屉里的「流式回答」开关控制。原因是契约里
`/agent/chat/stream` 不返回 `memoryCandidates`（避免标记混进增量文本），
而默认走同步 `/agent/chat` 才能拿到「要记住这条吗？」。开关关闭时是完整回答 + 记忆候选，
开启后是逐字返回、无候选；两种链路都在客户端实现。

### 2. 执行型智能体（`/agent/act`）

- 提交目标后拿 `taskId`，每 2 秒拉 `GET /agent/act/{taskId}`；
- `RUNNING` 期间就把已完成步骤画成时间线（思考 / 工具 / 观察），并显示 `currentStep`；
- 最终回答、课程/帖子来源、轮次与工具次数都来自同一个响应；
- `truncated` / `degraded` 会展示「已达到执行上限，结果可能不完整」等说明；
- 「停止」调用 `POST /agent/tasks/{taskId}/cancel`，轮询读到 `CANCELED` 后展示已保留步骤；
- 重新生成会带新的 `idempotencyKey`，避免命中后端 5 分钟幂等桶拿到旧任务。

### 3. 历史消息还原

`GET /agent/sessions/{id}/messages` 的四种 `contentType` 都有对应渲染：

| contentType | 渲染 |
|---|---|
| `text` / `image_text` | 普通气泡；用户图片按 `refsJson.images[].url` 还原 |
| `table` | 解析 `resultJson` 画表格（前 20 行 + 行数） |
| `task` 且 `SUCCESS` | `ppt → 演示卡`、`video_summary → 总结 + 字幕卡`、`video_subtitle → 字幕卡`、`act → 步骤 + 回答 + 来源` |
| `task` 且 `PENDING/RUNNING/FAILED/CANCELED` | 状态卡；`FAILED` 直接展示后端已清洗的中文 `errorMsg` |

执行任务的历史消息额外按 `taskId` 调 `GET /agent/tasks/{taskId}/steps` 补齐步骤，
再按 `beforeMessageId` 支持「加载更早」。

### 4. 模型提议的记忆

`/agent/chat` 返回的 `memoryCandidates` 渲染成「要记住这条吗？[保存] [忽略]」：

- 保存 → `POST /agent/memories`（`source=app`），后端按内容幂等；
- 忽略只在本地标记，不调接口；
- `candidateId` 作为本地去重键，同一条不会重复出现按钮。

### 5. 输入校验（与后端一致）

| 项 | 客户端行为 |
|---|---|
| PPT `topic` 100 字、`content` 8000 字 | 本地先校验，错误文案与后端同义 |
| `act.goal` 500 字 | 本地先校验 |
| 记忆单条 500 字、最多 50 条 | 输入框截断 + 面板显示 `n/50`，上限错误原样展示后端 `msg` |
| 聊天图片 ≤ 5MB，JPEG/PNG/GIF/WebP | 上传前压缩（长边 1600、质量 85），超限直接提示 |
| 最多 3 张图 | 当前只支持单图入口，未放开多图 |

## 四、后端已知小缺口（客户端已兜底）

1. **thought 步骤正文（已补齐）**：Python 的 act 事件里 `thought` 带 `content`（模型这一步想做什么），
   `ApiV1AgentActController.insertStep` 之前只落 `args`，正文丢了。现在后端把 `content` 写进
   `args_json`（`{"content":"..."}`），客户端 `AxingViewModel.argsText` 优先展示该字段，
   时间线里的「思考」能看到真实意图，不再只有「思考下一步」。
2. **`/chat/stream` 的图片入参**：控制器支持 `imageUrls`，但客户端流式提交目前不带图，
   图片提问统一走同步 `/chat`（同一条链路，结果一致）。
3. **`/agent/tasks/{id}/steps` 对 video/ppt 任务为空**：这两类任务只有进度没有步骤，
   客户端只用进度百分比。
