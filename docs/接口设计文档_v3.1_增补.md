## 一、统一内容项 `ContentItemDto`

### 1.1 为什么要统一定义

v3.0 的 4.2（分类内容列表）与 5.1（内容搜索）都只写了「**响应 data**: 分页列表」，
没有给出列表项的字段。缺这个定义会直接导致两个问题：

1. 客户端无法知道列表项的主键叫什么。6.1 课程列表返回 `courseId`、7.1 文章列表返回 `articleId`，
   如果 4.2/5.1 沿用各自的实体字段名，客户端就得按 `type` 分支解析；
   如果统一成 `id`，又和 6.1/7.1 不一致，容易出现「点进去 id=0」的空详情页。
2. 无法知道列表项是否携带 `type`，客户端在「混合分类」场景下无法判断点击后跳课程还是文章。

**本增补决定：4.2 与 5.1 的列表项统一为下表结构，主键字段名固定为 `id`，
并**必须**返回 `type`。** 6.1 / 7.1 保持原样（各自的 `courseId` / `articleId`），
两者不要互相套用。

### 1.2 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | long | 是 | **内容主键**。`type=1` 时为 `article.article_id`，`type=2` 时为 `course.course_id` |
| type | int | 是 | 1-文章 2-视频课程。**必须回传**，客户端据此决定跳文章详情还是课程详情 |
| title | string | 是 | 标题 |
| summary | string | 否 | 摘要/简介，列表页两行截断展示 |
| coverUrl | string | 否 | 封面图 URL，无封面返回空串 |
| categoryId | long | 否 | 所属分类 ID |
| categoryName | string | 否 | 所属分类名称，列表页角标展示 |
| authorId | long | 否 | 作者/讲师 ID（文章为作者，课程为讲师所属用户，无则 0） |
| authorName | string | 否 | 作者/讲师名称（课程取 `instructor_name`） |
| viewCount | int | 否 | 阅读数（文章）/ 播放数（课程） |
| likeCount | int | 否 | 点赞数 |
| commentCount | int | 否 | 评论数（课程无评论则返回 0） |
| duration | int | 否 | 视频时长（秒），文章返回 0 |
| score | double | 否 | 课程平均评分，文章返回 0 |
| createTime | string | 否 | 创建时间 `yyyy-MM-dd HH:mm:ss` |
| publishTime | string | 否 | 发布时间 `yyyy-MM-dd HH:mm:ss` |

  "message": "success",
  "data": {

    "list": [

        "coverUrl": "https://cdn.example.com/course/1024.jpg",
        "categoryId": 2,
        "categoryName": "商业",
        "authorId": 88,
        "authorName": "李老师",
        "viewCount": 12800,
        "likeCount": 320,
        "commentCount": 0,

        "score": 4.8,
        "createTime": "2026-01-12 09:30:00",
        "publishTime": "2026-01-13 10:00:00"

  "requestId": "uuid"

### 1.4 对 4.2 / 5.1 的字面修订

- **4.2 根据分类获取内容列表**：`响应 data` 由「分页列表」改为
  「分页列表，列表项为本文档 1.2 节 `ContentItemDto`」。
  Query 参数补齐默认值：`pageNum` 默认 1、`pageSize` 默认 20（最大 100）。
- **5.1 内容搜索**：`响应 data` 由「分页列表」改为
  「分页列表，列表项为本文档 1.2 节 `ContentItemDto`；`type` 与请求参数一致」。
- **5.1 补充约束**：`keyword` 为空串或缺失时按「全部内容」返回，
  此时 `type` 仍必填；若需要文章与课程混合返回，请新增 `type=0`（本增补不启用，
  客户端当前按单 `type` 查询）。

### 1.5 排序约定

| 接口 | `sort` 取值 | 含义 |
|---|---|---|
| 4.2 | 1 / 2 | 1 最新（`create_time` 倒序）2 最热（`view_count` 倒序） |
| 5.1 | 不适用 | 相关性优先，其次按 `publish_time` 倒序 |

## 二、注册接口细化（修订 2.2）

v3.0 的 2.2 只支持「手机号 + 短信验证码」。UI 与产品确认后需要同时支持**邮箱注册**。
本节给出双通道定义，替换 2.2 的原描述。

### 2.1 注册通道选择规则

`account` 字段统一承载账号标识，用 `accountType` 区分通道：

| accountType | account 含义 | 验证码通道 | 发送验证码 scene |
|---|---|---|---|
| 1（默认） | 手机号 | 短信 | `register` |
| 2 | 邮箱 | 邮件 | `register` |

> **兼容性**：为不破坏已按 v3.0 对接的调用方，服务端需同时接受旧的 `phone` 字段：
> 请求体中出现 `phone` 且没有 `account` 时，等价于 `account = phone`、`accountType = 1`。
> 客户端新代码一律使用 `account` / `accountType`。

### 2.2 密码注册（修订后）

- **URL**: `POST /api/v1/auth/register`
- **鉴权**: 否（匿名）
- **幂等**: 需要 `X-Idempotent-Token`

**请求参数（Body）：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| account | string | 是 | 手机号或邮箱，全局唯一 |
| accountType | int | 否 | 1-手机号（默认）2-邮箱 |
| password | string | 是 | 密码（6-20 位，至少包含字母与数字） |
| code | string | 是 | 对应通道的验证码，由 2.1 `send-code` 下发 |
| nickname | string | 否 | 昵称，不传则自动生成 |
| email | string | 否 | 邮箱。`accountType=2` 时可不传（等于 `account`）；`accountType=1` 时选填 |
| phone | string | 否 | **兼容字段**，见 2.1 说明 |

**响应 data**: 同 v3.0（accessToken + refreshToken + expiresIn + user）

**错误码**：

| code | 含义 |
|---|---|
| 1001 | 验证码错误 |
| 1002 | 验证码过期 |
| 1008 | 手机号已被注册 |
| 1009 | 邮箱已被注册（**新增**，与 1008 区分，便于客户端把错误定位到对应输入框） |
| 400 | 参数错误（account 格式非法 / password 强度不足） |

### 2.3 发送验证码（修订 2.1 的 targetType）

2.1 的 `targetType`（1-手机号 2-邮箱）保持不变，`scene=register` 时：

- `targetType=1`：走短信通道，60 秒限发一次，每日上限可配置
- `targetType=2`：走邮件通道，60 秒限发一次，邮件正文含 6 位数字验证码，`expireSeconds` 默认 300

### 2.4 登录（补充说明 2.3）

2.3 的 `username` 允许传：用户名、手机号、**或邮箱**。
三者在 `user` 表中分别落在 `username` / `phone` / `email`，服务端按「三选一命中」处理。

## 三、文件上传模块（新增第十五章）

> v3.0 只有资源下载（12.1），没有上传。拍照签到（9.2 的 `photoUrl`）、
> 文章封面（7.3 的 `coverUrl`）、笔记插图都缺一个统一入口，这里补上。
> 原「十五、后台管理通用接口」「十六、接口统计」「十七、v3.0 接口变更对照」
> 顺延为十六、十七、十八章。

### 15.1 上传文件

- **URL**: `POST /api/v1/files/upload`
- **鉴权**: 是（需登录）
- **幂等**: 需要 `X-Idempotent-Token`
- **Content-Type**: `multipart/form-data`
- **说明**: 统一上传入口。服务端校验 MIME 与魔数、按 `scene` 归档路径、生成唯一文件名，
  返回可直接落库到 `*_url` 字段的公网访问地址。

**请求参数（multipart form-data）：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | file | 是 | 文件本体。单文件，字段名固定为 `file` |
| scene | string | 是 | 业务场景，取值见下表 |

**scene 取值与约束：**

| scene | 用途 | 落库位置 | 允许 MIME | 大小上限 |
|---|---|---|---|---|
| avatar | 用户头像（3.2 `avatar`） | `user.avatar` | image/jpeg, image/png, image/webp | 2 MB |
| article_cover | 文章封面（7.3 `coverUrl`） | `article.cover_url` | image/jpeg, image/png, image/webp | 5 MB |
| article_image | 文章正文内嵌图 | 无（正文 HTML 内） | image/jpeg, image/png, image/webp, image/gif | 5 MB |
| note_image | 笔记插图（10.2 `content`） | 无（正文内） | image/jpeg, image/png, image/webp | 5 MB |
| checkin_photo | 拍照签到（9.2 `photoUrl`） | `checkin_record.photo_url` | image/jpeg, image/png | 5 MB |
| course_cover | 课程封面（后台上传） | `course.cover_url` | image/jpeg, image/png, image/webp | 5 MB |
| resource | 课程配套资源（12.1 下载） | `resource.file_url` | 见 12.1 | 100 MB |

**响应 data：**

```json
{
  "fileId": "a1b2c3d4e5f6",
  "url": "https://cdn.example.com/avatar/2026/02/18/a1b2c3d4e5f6.jpg",
  "fileName": "avatar_20260218.jpg",
  "fileSize": 184320,
  "mimeType": "image/jpeg",
  "width": 512,
  "height": 512,
  "scene": "avatar",
  "createTime": "2026-02-18 14:32:10"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| fileId | string | 是 | 文件唯一标识，删除时使用 |
| url | string | 是 | **公网可访问的完整 URL**，客户端直接落库到对应 `*_url` 字段 |
| fileName | string | 是 | 服务端生成的文件名 |
| fileSize | long | 是 | 字节数 |
| mimeType | string | 是 | 服务端识别出的真实 MIME（不信任客户端声明） |
| width | int | 否 | 图片宽（px），非图片返回 0 |
| height | int | 否 | 图片高（px），非图片返回 0 |
| scene | string | 是 | 回显请求的 scene |
| createTime | string | 是 | 上传时间 |

**错误码：**

| code | 含义 |
|---|---|
| 401 | 未登录 |
| 400 | 参数错误（缺 file / scene 非法） |
| 7001 | 文件类型不允许（MIME 或魔数校验失败） |
| 7002 | 文件超过大小上限 |
| 7003 | 文件内容为空 |
| 429 | 上传限流（同用户 20 次/分钟） |
| 500 | 存储服务异常 |

> **错误码分段说明**：v3.0 的 1.4 把 7001-7099 分配给「笔记待办」，
> 但那一段目前只用了逻辑错误码。此处占用 7001-7003 作为文件错误码，
> 笔记/待办的逻辑错误码从 7010 起编。若后端已按 7001+ 给笔记编号，
> 请把文件错误码改到 9101-9103（本增补可调整，取一处统一即可）。

### 15.2 删除文件

- **URL**: `DELETE /api/v1/files/{fileId}`
- **鉴权**: 是（仅本人上传的文件，或管理员）
- **说明**: 头像/封面替换成功后再调用，删除旧文件，避免对象存储堆积

**响应 data**: `{}`

**错误码**: 403 非本人上传 / 404 文件不存在

### 15.3 客户端约束（给 Android 端的落地约定）

1. **上传前本地压缩**：图片统一压到长边 ≤ 1600px、JPEG 质量 85，
   避免把手机原图（5-10 MB）直接推上去。
2. **字段名必须是 `file`**：Retrofit 侧用
   `MultipartBody.Part.createFormData("file", fileName, requestBody)`。
3. **`scene` 必传**，服务端以此决定归档目录与大小上限；客户端不做类型白名单之外的猜测。
4. **上传成功拿 `url` 落库**，不要自己拼 CDN 前缀。
5. **上传与业务写入是两步**：先 `POST /files/upload` 拿到 `url`，
   再调 9.2 签到 / 7.3 发文章 / 10.2 建笔记把 `url` 带上。
   若第二步失败，`url` 仍需在 15.2 清理（客户端可延迟清理，不强制）。

## 六、给后端的落地清单

按优先级排，前两项不确认客户端就发不出功能：

1. **4.2 / 5.1 的列表项按第 1.2 节返回**，尤其是 `id` 与 `type` 两个字段。
   现在客户端已按此实现（`ContentItemDto`），若字段名不同，搜索结果点击会跳空详情页。
2. **15.1 上传接口**：路径 `POST /api/v1/files/upload`、字段名 `file` + `scene`、
   返回 `url`。拍照签到、文章封面、笔记插图三个功能都卡在这里。
3. **2.2 双通道注册**：确认 `account` / `accountType` 命名，或告知沿用 `phone` 字段
   而由服务端按格式判断手机号/邮箱（那种情况下客户端可以不传 `accountType`）。
4. **验证码有效期**：`send-code` 返回的 `expireSeconds` 客户端用来做倒计时，
   当前按 300 秒展示，若实际 60 秒请同步。
5. **图片访问域名**：`url` 是否为公网 HTTPS、是否需要 Referer 白名单。
   当前客户端 `usesCleartextTraffic=false`，**只能是 HTTPS**。
