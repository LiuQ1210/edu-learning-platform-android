# 若依（RuoYi）后端 × Android 客户端 冲突对照表

> 结论先说：**没有原则性冲突，但有 5 条必须改，其中 1 条不改则每个请求都失败。**
> 修改建议**全部放在后端**（若依侧加适配层），客户端不动。

---

## 一、致命冲突（不改则全线失败）

### 1. 成功码不一致 —— 每个请求都会被判为失败

| | 约定 |
|---|---|
| **客户端** | `Constants.CODE_SUCCESS = 0`，`safeApiCall` 里 `if (code != 0) throw ApiException` |
| **若依默认** | `AjaxResult` 用 `code = 200` 表示成功（`HttpStatus.SUCCESS`） |

**后果**：若依返回 `{"code":200,...}`，客户端认为不是成功码 → **抛异常**。首页、登录、列表，**全部失败**。

**修法（后端，推荐）**：加一个 `ResponseBodyAdvice`，把所有响应统一包成 `code = 0`。

```java
@RestControllerAdvice
public class ApiResponseAdvice implements ResponseBodyAdvice<Object> {
    @Override
    public boolean supports(MethodParameter r, Class<? extends HttpMessageConverter<?>> c) {
        return true;   // 可按包名限定，避免影响若依自带的管理端接口
    }

    @Override
    public Object beforeBodyWrite(Object body, MethodParameter r, MediaType t,
                                  Class<? extends HttpMessageConverter<?>> c,
                                  ServerHttpRequest req, ServerHttpResponse res) {
        if (body instanceof ApiResponse) return body;          // 已包装则跳过
        long ts = System.currentTimeMillis();                   // 注意：毫秒，不是秒
        String traceId = MDC.get("traceId");
        return Map.of(
            "code", 0,
            "message", "success",
            "data", body,
            "timestamp", ts,
            "requestId", traceId == null ? "" : traceId
        );
    }
}
```

**同时要改异常处理器**：若依的 `GlobalExceptionHandler` 默认返回 `code = 500`，客户端会当成服务端错误。业务错误码要按客户端的 1001~9199 分段映射。

> **注意**：若依自带的管理端（PC 后台）也走这个 `@RestControllerAdvice`。建议用**包名限定**（`supports()` 里判断 `r.getContainingClass().getPackageName()`），只对 `/api/v1/**` 生效，别把管理端接口也改了。

## 二、必须改（功能可用但行为错误）

### 2. 分页字段名不一致

| | 约定 |
|---|---|
| **客户端** | `PageData<T> { total: Long, list: List<T> }` |
| **若依（PageHelper）** | `TableDataInfo { total: long, rows: List<T>, code, msg }` |

**后果**：客户端 `list` 永远为空 → 列表页全空（不报错，只是没数据，**更难排查**）。

**修法（后端）**：同样在 `ResponseBodyAdvice` 里识别 `TableDataInfo`，转成 `{total, list}`。
**别选另一条路**（改客户端 DTO 加 `@SerialName("rows")`）——客户端已有 13 个仓库依赖 `list`，改动面更大。

### 3. 时间戳格式不一致

| | 约定 |
|---|---|
| **客户端** | `timestamp: Long`（毫秒）。**全部业务时间字段是 `String`**（`createTime`、`publishTime`、`signTime`、`deadline`…），格式 `"yyyy-MM-dd HH:mm:ss"` |
| **若依默认** | `AjaxResult` 里通常**不带** `timestamp`；日期用 `@JsonFormat(pattern="yyyy-MM-dd HH:mm:ss")` |

**好消息**：业务时间字段两边**都是字符串**，不冲突。

**要处理的**：
- 外层 `timestamp` 若依没有 → 上面 `ResponseBodyAdvice` 里补上，**必须是毫秒**
- 若若依配了全局 `ObjectMapper` 把日期序列化成 `Long`（部分版本会），会与客户端 `String` 冲突 → 确认 `spring.jackson.date-format` 和 `time-zone`（客户端按 `Asia/Shanghai` 解析）

### 4. 文件上传返回值不一致

| | 约定 |
|---|---|
| **客户端** | `UploadFileDto { fileId, url, fileName, fileSize, mimeType, width, height, scene, createTime }` |
| **若依默认** | `FileUploadUtils.upload()` 返回**相对路径**（如 `/profile/upload/2026/09/22/xxx.png`），响应体 `{code, msg, fileName, url, newFileName, originalFilename}` |

**后果**：客户端拿到的 `url` 是相对路径 → 图片加载失败（Coil 无法解析）。

**修法（后端）**：封装一个 `/api/v1/files/upload`，返回**完整可公开访问的 URL**（带域名或 CDN），并生成 `fileId`、补 `mimeType`。若依的返回里没有 `fileId`，需要落库生成。

### 5. 登录/注册字段与流程不一致

| | 约定 |
|---|---|
| **客户端** | 注册：`account` + `accountType`(1 手机 / 2 邮箱) + `code` + `password`；登录：账号密码 + **图形验证码**（错误码 1001/1002） |
| **若依默认** | `SysLoginService` 走 `username` + `password` + **图形验证码**；注册功能**默认没有** |

**修法（后端）**：按客户端的 11 个 `/auth/*` 端点自己写 Controller，复用若依的 `SysUserService`、`TokenService`。
- `accountType=1` → 写入 `sys_user.phonenumber`；`=2` → 写入 `email`；**未使用的那一列必须是 `NULL`，不能是 `''`**（否则唯一索引会冲突）
- `username` 由服务端生成（如 `user_{id}`），客户端不传
- 图形验证码若依有现成的（`CaptchaController` + Redis），可复用

## 三、需要评估（取决于需求）

### 6. 双 Token 刷新轮换 —— 若依默认没有

| | 约定 |
|---|---|
| **客户端** | accessToken（2h）+ refreshToken（7d），**轮转制**：刷新时旧的 refreshToken 立即作废；收到 401 自动刷新并重放请求；**并发安全**（锁 + 「token 是否已被换过」判断） |
| **若依默认** | 单 token（`Authorization: Bearer <token>`），存 Redis，靠滑动过期续期；**没有 refreshToken 概念** |

**这是个真缺口。** 要支持客户端的 `TokenAuthenticator`，后端必须：
1. 签发两个 token（access + refresh），各自 TTL
2. 提供 `/auth/refresh`，**轮转制**（旧 refresh 立即失效）
3. 客户端并发 401 时会用**同一个** refreshToken 打两次，后端必须能处理（要么幂等，要么第二次返回明确错误让客户端重试）

**如果后端不想做**：客户端可以降级——去掉 refresh，401 直接跳登录页。**代价是用户每 2 小时被登出一次**，体验很差。建议后端做。

### 7. 幂等头 `X-Idempotent-Token` —— 若依默认没有

客户端在**所有写操作**上带 `X-Idempotent-Token`（点赞、收藏、发评论、发布文章等）。

**修法（后端）**：加一个拦截器 + Redis `SETNX`（键 = token，TTL 如 10 分钟），命中则直接返回上次结果。工作量约 0.5 人日。

**若不做**：客户端会重复提交（用户连点两次点赞 → 两条记录）。**建议做**，成本低。

### 8. 评论的游标分页 —— 若依只支持 offset

| | 约定 |
|---|---|
| **客户端** | 评论用**游标分页** `{hasMore, nextCursor, list}`；其他列表用 offset `{total, list}` |
| **若依** | PageHelper 只做 offset 分页 |

**修法（后端）**：评论接口单独写，不走 PageHelper，用 `WHERE id < :cursor ORDER BY id DESC LIMIT :size`。

### 9. 错误码分段 —— 若依是一套通用码

客户端按 **1001-1099 鉴权 / 2001-2099 用户 / 3001-3099 课程 / 4001-4099 文章 / 5001-5099 互动 / 6001-6099 签到 / 7001-7099 笔记待办 / 8001-8099 搜索分类 / 9001-9099 下载广告 / 9101-9199 文件上传** 分段。

若依的 `GlobalExceptionHandler` 返回通用码（500、401 等）。需要**按业务补映射表**，否则客户端的友好提示（"邮箱已被注册"、"验证码已过期"）全都退化成"操作失败"。

## 四、不冲突的（可以放心）

| 项 | 说明 |
|---|---|
| **HTTP 方法/路径风格** | 客户端用 RESTful（`GET /content/list`、`POST /interaction/like`），若依 Controller 可以照写，不冲突 |
| **认证头格式** | 两边都是 `Authorization: Bearer <token>`，**一致** |
| **JSON 序列化** | 都是 JSON，字段命名都是 camelCase，**一致** |
| **文件上传方式** | 都是 `multipart/form-data`，**一致** |
| **时间字段（业务层）** | 两边都是字符串 `"yyyy-MM-dd HH:mm:ss"`，**一致** |
| **业务表结构** | 数据库设计文档的 34 张表是业务表，若依的 `sys_user`/`sys_role` 等系统表可共存，不冲突 |

## 五、落地建议

### 后端改造清单（按优先级）

| 优先级 | 项 | 估时 |
|---|---|---|
| P0 | 统一响应包装（code=0 / timestamp 毫秒 / requestId） | 0.5 人日 |
| P0 | 分页 `rows` → `list` 转换 | 0.5 人日 |
| P0 | 登录注册 11 个端点（复用 SysUserService） | 2 人日 |
| P0 | 文件上传返回完整 URL + fileId | 0.5 人日 |
| P1 | 错误码分段映射 | 1 人日 |
| P1 | 评论游标分页 | 0.5 人日 |
| P1 | 双 Token 刷新轮换 | 1.5 人日 |
| P2 | 幂等拦截器 | 0.5 人日 |
| | **合计** | **约 7 人日** |

### 两条路线，选一条

**路线 A（推荐）：后端加适配层，客户端不动。**
约 7 人日。收益：客户端的 13 个仓库、58 处预览短路点、错误码映射全部不用改。

**路线 B：改客户端去适配若依。**
不建议。要动 `ApiResponse`、`PageData`、13 个仓库的解包逻辑、错误码表、鉴权刷新的全部实现，**改动面比后端大得多**，而且会让客户端与接口文档 v3 不一致（文档已经交付了）。

### 一个前提要先确认

- **若依是哪个版本？** `RuoYi`（Spring Boot 3 + Vue3 前后端分离版）和 `RuoYi-Cloud` 的 Security 配置差异较大，影响第 5、7 条的实现方式
- **是 JWT 还是 Redis 存 session？** 若依默认是 Redis 存 token（`TokenService`），这反而**有利于**做 refresh 轮换（Redis 天然支持 TTL 和主动失效）
